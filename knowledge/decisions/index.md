# Decisions

* [Roadmap to the agentic change flow](agentic-flow-roadmap.md) - What reliab and a consumer's profile need for an agent to take a change edit to PR with the evidence the paper's change timeline shows, plus on-demand testing; CI and nightly work are deferred to the end.
* [Binary delivery: a launcher that fetches the pinned release](binary-distribution.md) - plugin/bin/reliab is a POSIX sh launcher that downloads and caches the versioned binary; install scripts do the same for any CI.
* [CI-agnostic: no CI templates, gates are commands](ci-agnostic.md) - reliab writes no CI files or CODEOWNERS; CI runs documented commands and reads exit codes, and wires approvals with its own host features.
* [Claude Code first, with its hook protocol isolated](claude-code-first.md) - Target Claude Code, but keep its hook stdin/stdout formats in one internal package.
* [reliab makes no assumptions about where it is used](context-agnostic.md) - The tool and repo never refer to any particular deployment, organisation, or private system.
* [First targets: reliab itself and a real consumer repository](dogfood-targets.md) - v0 is proven on reliab's own repo (Go, greenfield) and on a real consumer repository in another ecosystem, plus a fixture service under testdata/.
* [Enforcement hooks decide for themselves; CI gates are authoritative](enforcement-hooks-self-contained.md) - Enforcement hooks match every relevant tool call without if filters and parse the command in reliab; in-session enforcement is best-effort and CI decides.
* [Adapters emit unclassified findings; the agent classifies](finding-classification.md) - Every adapter finding starts unclassified; reliab findings classify records the kind; hooks block on unclassified.
* [The CLI is written in Go](go-cli.md) - Single static binaries per OS, fast hook startup; latest stable Go (1.27.2) with cobra and minimal dependencies.
* [Spike undocumented hook behavior before building hook logic](hook-behavior-spike.md) - Superseded: the design no longer depends on the answers, so the spike was dropped.
* [What the v0 hooks decide](hook-decisions-v0.md) - pre-edit, pre-bash, stop, and session-start rules; human-only acknowledgement; fail open on a broken profile; never exit 2 on a hook error.
* [Impacted tests: a glob-to-arguments map in the profile](impacted-tests-map.md) - reliab stays stack-ignorant; the profile maps changed-file globs to test command arguments, falling back to everything.
* [The inner tier runs when a change is done, not after each edit](inner-tier-trigger.md) - Agents run verify --tier inner once a logical change is complete, before stopping; the stop hook enforces it. Mid-change edits are never interrupted.
* [A mutation threshold on changed code, and a baseline ratchet per scope](mutation-threshold.md) - A mutation command may set a threshold; a protected baseline file records a score per scope. verify adds a derived below-threshold finding per shortfall, never classified; report summary shows the scores; reliab gate mutation fails below them; a person writes the baseline with reliab baseline write.
* [Mutation: baseline first, then hold the line](mutation-baseline-first.md) - On a maintained codebase the first mutation run records a baseline with no threshold; the gate then requires changed code not to fall below it.
* [Project knowledge is an OKF v0.2 bundle in knowledge/](okf-knowledge-bundle.md) - Decisions and understanding are stored as Open Knowledge Format concepts, not a separate ADR folder.
* [Onboarding: stage S0 as a skill the agent runs](onboarding-skill.md) - The plugin's onboard skill walks an agent through S0: init with the starting condition, a read-only inventory, repeated suite runs that list flaky tests, a probe through reliab verify for every role filled, tiers within budget, and a stop at the S0 gate with a report; it never edits product code or existing tests. Example profiles for Go, Rust, and .NET ship in templates/examples.
* [On-demand characterization: capture, change, compare, discard](on-demand-characterization.md) - A characterize profile command writes transcripts of an area into {capture}; reliab characterize capture, compare, and discard keep the captures under .reliab/, label each difference, and never commit or approve anything. The characterize skill drives the cycle.
* [reliab's own repo dogfoods and releases with goreleaser](own-release-pipeline.md) - This repo's GitHub Actions workflow runs reliab on itself and publishes cross-platform binaries and checksums on tags.
* [The paper is design intent, not a fixed spec](paper-as-design-intent.md) - reliab keeps the structure of the evidence-stack paper and records every departure as a Decision.
* [Explicit path classes; unmatched files count as product](path-classification.md) - The profile declares product, tests, and ignore globs; anything unmatched is product, so gaps make hooks stricter.
* [v0 pre-push gate without a reviewer verdict](pre-push-v0.md) - Pre-push requires a fresh, complete pre-PR report with no blocking findings; the verdict check waits behind a flag.
* [Public repository, no open-source license](public-repo.md) - reliab is public at hbaldwin98/reliab with no license file; the Go module path follows.
* [A person approves a protected-path change locally with reliab approve](protected-path-approval.md) - reliab approve records the blob hashes of a protected file's change in .reliab/approvals.json; gate protected, the PR summary, and the reviewer accept matching content and list it apart, and any later edit voids it. Hooks deny it to agents; approvals are local, so CI and the code host's owner review stay authoritative.
* [Protected paths: four layers of enforcement](protected-path-enforcement.md) - Deny rules, a Bash heuristic hook, sandbox denyWrite where supported, and the gate command; the native-Windows gap is documented.
* [The PR's evidence section is rendered from the report](pr-evidence-summary.md) - reliab report summary renders a tier's latest report (default prepr) as Markdown or JSON for a PR body: what ran, skips and why, mutation counts and survivors, findings open, acknowledged, and fixed during the change, and the questions for a human. It states only what reports say, and flags a stale or incomplete report at the top.
* [Relevance skips: a layer the change cannot affect is skipped, saying why](relevance-skips.md) - A command may declare relevant_when globs; inner and prepr skip it with reason not-relevant when no file changed since the base matches; never in nightly, under --only, or without a base. Summary and route show the skip and why commands ran.
* [A report names the profile file it ran with](report-profile-path.md) - verify records the profile file it loaded as run.profilePath (report 0.12.0); commands that judge a report load it when reliability-profile.yaml protects it, and protection always reads reliability-profile.yaml.
* [Report freshness is a working-tree hash](report-freshness.md) - Reports record a tree hash built from a temporary git index; hooks compare it to the current tree.
* [The reviewer subagent and its tree-bound verdict](reviewer-verdict.md) - A plugin agent without edit tools re-runs prepr in a clean worktree, reads the diff against R1 to R5 and R7, and records a verdict with reliab report verdict. The pre-bash hook allows that command only to the reliab:reviewer agent; a pass needs a matching re-run and is bound to the report's tree hash, so any edit voids it. Threat model and limits included.
* [Reports live in .reliab/reports/ and only reliab writes them](report-storage.md) - Reports are gitignored and denied to agent edits so an agent cannot forge a clean report.
* [Snapshot diffs are labelled additive-only or values-changed](snapshot-diff-labels.md) - A text snapshot or capture that no longer matches carries an optional diff label in the findings and report formats; route shows it. The rule is generic and public: pkg/snapdiff and reliab snapdiff, for any adapter. reliab-adapter-insta and reliab-adapter-verify read their tools' pending files.
* [Shape of the 0.x profile and report schemas](schema-v0-shape.md) - Field-level choices in schemas/: fixed command ids, placeholders, impacted args, output formats, and report fields.
* [Own JSON Schemas, semver, strict; SARIF and JUnit exports](schemas-and-versioning.md) - Profile and report schemas are JSON Schema 2020-12 with a semver schemaVersion and strict keys; the report exports to SARIF and JUnit.
* [One repo: CLI, schemas, plugin, and a plugin marketplace](single-repo-marketplace.md) - The repo root is a Claude Code marketplace; the plugin lives in plugin/ beside the CLI and schemas.
* [Tier defaults, budget overruns, and exit codes](tiers-budgets-exit-codes.md) - Figure 1 is the built-in tier default, overridable in the profile; overruns mark the report incomplete; exit codes 0 to 3.
* [v0 scope and definition of done](v0-scope.md) - v0 is the core CLI plus a minimal plugin; done is a real edit-to-PR loop on a real consumer repository with hooks enforcing the rules.
* [reliab reads interchange formats; adapters convert the rest](external-adapters.md) - The core reads JUnit, TRX, mutation-testing-elements, Cobertura (counts only), and its own findings format. Tool-specific output is converted by separate adapter programs that anyone can write; reliab exposes the rules adapters share as CLI helpers and public Go packages. reliab's own adapters live in cmd/adapters and ship beside the binary.
* [Named tests: verify takes the tests that guard the change per run](named-tests.md) - verify --tests (one test run per flag) and --mutation-tests name the tests that guard the change, in any tier; reliab passes them through as opaque text in {tests}, {mutation_tests}, RELIAB_TESTS, and RELIAB_MUTATION_TESTS and records them in the report; a command whose profile needs them, run without them on a relevant change, leaves the run incomplete (needs-input) and the hooks wait.
* [On-demand verify: chosen commands, chosen paths, a separate report](on-demand-verify.md) - verify --only runs named profile commands under a tier's budget, --scope narrows them to paths, and the run writes an on-demand report that never satisfies the stop or push hooks.
* [How verify runs commands](verify-execution.md) - Commands run under sh from the repo root with logs in .reliab/out; outputs may be globs; a failed build skips the rest; budget overruns kill the whole process tree; finding ids are stable so classifications carry forward.
* [CLI and plugin share one version](versioning-lockstep.md) - One semver tag releases the binary and stamps the plugin version; consuming repos pin it in .reliab-version.
